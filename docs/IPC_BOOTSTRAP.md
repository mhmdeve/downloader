# Native host IPC bootstrap contract

The native host resolves its bootstrap file with the platform's user configuration directory (dirs::config_dir()):

- Linux: $XDG_CONFIG_HOME/internet-downloader/ipc.json (or ~/.config/internet-downloader/ipc.json)
- macOS: the user configuration directory returned by the Rust dirs crate, under internet-downloader/ipc.json
- Windows: the per-user configuration directory returned by dirs, under internet-downloader\\ipc.json

The file is runtime state and MUST NOT be committed, logged, or passed as command-line arguments. Its JSON shape is:

    {"port":12345,"token":"<at-least-32-random-bytes-encoded-as-hex>"}

The port must be the actual ephemeral port returned by binding the app's TCP listener to 127.0.0.1. The token must be generated by an operating-system cryptographically secure random source for each app session and contain at least 32 bytes of entropy. Hex encoding is recommended (64 hex characters for 32 random bytes).

The desktop app bootstrap writer (still to be implemented in M7) must:
1. Create the parent directory in the current user's config directory; on Unix, set the directory to mode 0700.
2. Write a temporary file in that same directory, set mode 0600 on Unix before writing secrets, flush it, and atomically rename it to ipc.json.
3. On Windows, keep the file under the user's profile with inherited user-only ACLs or explicitly set a DACL restricted to the current user and SYSTEM.
4. Remove the bootstrap file on clean shutdown and rotate the token on every startup.
5. Never log the token or expose it to web content. Only the native messaging host should read it.

The host rejects missing, symlinked/non-regular, oversized, broadly permissioned Unix files, invalid ports, and short tokens. It connects only to IPv4 loopback, sends the token in the versioned JSON request, uses a three-second socket timeout, and caps the request/response line at 64 KiB. If the file is absent or the app is unavailable, it returns a structured APP_NOT_RUNNING error to the browser.

This contract does not complete M6 by itself: the desktop app must still generate/write the file, start the IPC service, and run end-to-end tests across the browser framing boundary.
